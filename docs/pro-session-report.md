# تقرير جلسة التنفيذ (Pro)

تضيف هذه الميزة تصديرًا محليًا إلى Markdown **لسجل الجلسة المسجّل بالفعل**. يلخّص التقرير استدعاءات الأدوات بالترتيب، وحالة كل دعوة (`نجح` أو `فشل` أو `غير مكتمل`) وعدّاداتها. لا يعيد تشغيل أدوات، ولا يستدعي نموذجًا لغويًا، ولا يتبع روابط أو يقرأ ملفات أثناء التصدير.

## حدود الخصوصية

لا يتضمن التقرير نص الطلب أو معلمات الأدوات أو معرّفات الاستدعاء أو الصور. يختصر مخرج الأداة الفعلي بعد تنقيح واسع للمفاتيح والرموز المميزة وكلمات المرور والأسرار وروابط ومسارات الملفات الخاصة، ويهّرب HTML وMarkdown الديناميكي. يكتب التقرير داخل `workspace` فقط، في ملف جديد بصلاحية `0600`، ولا يستبدل ملفًا موجودًا.

## حد الاستحقاق

`ToolCallAgent.export_pro_session_report(...)` هو مدخل التكامل للمضيف الموثوق. يتطلب:

1. `account_id` من جلسة مصادَق عليها، لا من علم CLI أو رابط أو تخزين محلي؛
2. `EntitlementVerifier` متصلًا بخدمة خادمية تملك سجل الاشتراكات الدائم؛
3. استحقاقًا عائدًا للحساب نفسه وحالته `active` وغير منتهٍ.

يفشل `UnconfiguredEntitlementVerifier` مغلقًا بحالة «إعداد شراء مطلوب». وتُرفض حالات الإلغاء والانتهاء والتأخر والحساب غير المطابق. حقن `StaticVerifier` محصور في الاختبارات ولا يوجد مسار نشر يمنح الاستحقاق محليًا.

يظهر الخيار `--export-session-report PATH` في CLI الحالي حتى يكون مدخل الميزة قابلاً للاكتشاف، لكنه لا ينشئ تقريرًا في هذه النسخة: التطبيق لا يملك مصادقة حسابات أو موصل استحقاق خادمي بعد، ولذلك يسجل حالة الإعداد المطلوب بدلاً من قبول هوية أو عملية شراء مزيفة.

## ما يلزم قبل إتاحة الشراء

لم يُختر بعد بلد التحصيل أو مزود الدفع أو قناة توزيع Android. قبل الإطلاق، يجب ربط شراء مناسب للقناة مع جهة خادمية تتحقق من هوية الحساب وملكية البيانات، وتخزن ربط العميل/الاشتراك/أحداث الدفع، وتتحقق من توقيع الأحداث، وتعالج إعادة التسليم بصورة قابلة للتكرار. لا يجوز جعل الدفع أو الاستحقاق يستند إلى متغير عميل أو `localStorage` أو query string أو حالة واجهة المستخدم.
